# C_REASONING_MODEL — C 到底在解決什麼問題（審計任務 1+2）

> 純分析文件，深度自審產物。不改變凍結結論；不構成 READY 證據。

## 1. C 為什麼存在

專案地圖（Project Map）是人類維護的架構信念：節點＝職責，邊＝關係。它必然落後於程式碼。B 能抽出「某個 pinned 版本裡有哪些宣告」，A 能算出「兩個版本之間路徑級的變化」，CA 維護「關於本專案的外部主張及其驗證狀態」——**但沒有任何一層能回答「這次變化對架構地圖意味著什麼」**。

C 存在的理由：把「程式碼變了」到「地圖該怎麼改」之間的鴻溝拆成兩半——
1. **證據蒐集與交叉比對是機械的**（diff × 宣告 × 地圖證據域 × CA 主張）→ C 做；
2. **「這次變化是否改變架構職責/關係」是推斷** → C 只提出候選（hypothesis）+ 完整證據鏈，把裁決權完整交還人類。

所以 C 的產品本質是三件事：**證據聚合器、提案起草者、注意力路由器**（把人類該看的東西用 HUMAN_REQUIRED/unresolved 精確路由，不製造噪聲也不吞掉疑點）。C 不是架構師，不是地圖編輯器，不是事實來源。

## 2. 五層邏輯鏈：每層提供什麼、不能提供什麼、失效怎麼辦、誰有最終權限

| 層 | 提供什麼（FACT 類） | 不能提供什麼 | 失效時的姿態 | 最終權限 |
|---|---|---|---|---|
| **Git diff（A/caller 提供）** | 路徑級變化事件（added/modified/removed/renamed）、pinned patch/blob | 語義、意圖、架構重要性；它甚至不提供「哪些變化彼此相關」 | pin 缺失/不合法 → 整個請求受控拒絕（不是降級——沒有 pin 一切無從談起）；不得自行重算 diff（口徑分叉） | A/caller 擁有 diff 口徑；C 是消費者 |
| **B facts（宣告）** | revision + files[{path, entries[name/kind/line]}] + skipped——即「這個版本裡宣告了什麼符號」 | import、呼叫圖、簽名、職責、意圖；**skipped 路徑連宣告都沒有** | B 不可用 → 顯式 DEGRADED，只跑不需要 B 的安全分支；B skipped → 該路徑的**事實基礎整體作廢**，任何依賴它的強推斷都失去地基 | B owner；C 絕不在執行時重新解析宣告來「補貨」 |
| **Current Map（人類地圖）** | 人類當前的架構信念原文：nodes（職責宣告 + evidence 路徑域）+ edges（關係主張） | **任何版本身份**——沒有人能證明這份地圖對應哪個 SHA；node 職責描述是信念不是事實 | 形狀不合法 → 受控拒絕；地圖過期 → 只能以「候選 + 地圖可能過期」的措辭呈現，永不斷言「節點已死」 | 人類（地圖所有者）；C 永不寫入 |
| **CA（Context Authority）** | 帶驗證狀態與出處的專案主張（claims）+ 衝突清單 + 不可驗證清單 | **外部世界的當下真值**——結構合法 ≠ 事實為真；PR 狀態/實作狀態必須獨立核驗 | pack 校驗失敗 → 整包棄用；conflict → 相關候選轉 HUMAN_REQUIRED、C 不選邊；unavailable → UNKNOWN/limits，不偽裝壞包 | CA owner + 獨立核驗；pack 自稱的值不是 oracle |
| **Human Review** | 接受/拒絕/修改提案；地圖的最終編輯權 | —— | —— | **人類是一切架構判斷與地圖變更的唯一權限**；C 的輸出永遠 PROPOSED + human_required |

推論：C 的每一種輸出都必須能在這條鏈上指出「我的證據來自哪幾層、哪一層沒有發言權」。凡是把某一層「不能提供的東西」當成了證據，就是缺陷（F01 把 B 當架構真值；F03 把 CA 當事實；F05 把宣告通道的裁決當成關係通道的裁決）。

## 3. 不可違反不變量（從契約推導的語義規則，不是測試名）

### SAFETY（不造成傷害）
- **S-1 地圖神聖性**：C 不寫地圖、不建議 position、不自行 accept/reject——不是「沒有實作寫入路徑」而已，而是任何輸出結構中都**不得出現**可被誤用為「已套用」的欄位。
- **S-2 結構合法 ≠ 外部事實為真**：任何通過 validator 的 pack 主張，其「外部真值」（PR 狀態、實作狀態、contract 形狀）仍然未知；未經獨立核驗不得支撐任何事實斷言。UNVERIFIED 標籤是誠實聲明，不是洗白通道。
- **S-3 一切有 pin**：所有證據讀取都釘在顯式 revision 上；不讀工作樹補證據；錯誤訊息不洩漏環境機密。
- **S-4 生命週期屬於人**：PROPOSED/human_required 不可被 C 單方面改變；人類 REJECTED 且 subject/kind 相同的候選保持抑制（F20），但 C 不得「永久封禁」——理由實質變化時允許重新待審。

### CORRECTNESS（不下錯誤結論）
- **C-1 候選由交叉信號定義**：每種 kind 只在其定義性交叉信號成立時發出（例：NODE_ADD ≡ 新路徑 ∧ 無地圖覆蓋 ∧ 有合格宣告 ∧ 非噪聲）。單一來源（「B 有這個檔案」）永遠不足以構成任何 kind。
- **C-2 通道獨立**：「宣告沒變」是宣告通道的裁決，不是整個檔案分析的裁決；任何通道不得替其他通道早退。
- **C-3 證據缺失 ≠ 反向證據**：解析失敗/讀取失敗/無法解析的形式 → UNKNOWN，永不等同「零」；B 無條目 ≠ 模組在架構上不存在。
- **C-4 刪除類證據是全域性的**：RELATION_REMOVE 的證明域是「source 職責域 → target 職責域之間的依賴證據是否真正消失」，不是「某檔案刪了一行 import」；NODE_REMOVE 的證明域是節點全部 evidence 路徑在 pinned target 的確定存在性。

### EVIDENCE（證據紀律）
- **E-1 可回放**：每個 proposal 至少一條可定位 (revision, path) 的事實證據；被選中的關鍵證據（主宣告、兩端節點）不得截斷。
- **E-2 事實與推斷分離**：diff/宣告/地圖原文 = FACT；職責/關係含義/入口選擇 = INFERENCE；rationale 不得把 INFERENCE 裝扮成 FACT。
- **E-3 skipped 毒化整個依賴子樹**：B skipped 不是「一個 if」，而是「該 source 的事實基礎整體作廢」——任何通道、任何以它為證據域端點的強推斷全部失去資格，轉 HUMAN_REQUIRED。
- **E-4 CA 消費必須有型別化的用途**：claim 進入證據需要 (a) 明確的消費用途，(b) 按欄位的驗證支援（verified_fields），(c) 高影響事實的獨立核驗。三者缺一 → 只能進診斷/limits，不進 evidence。

### OWNERSHIP（職責邊界）
- **O-1 各層產品不可代工**：diff 口徑 = A；宣告解析 = B；pack 真值 = CA + 獨立核驗；地圖 = 人類。C 在執行時重新解析宣告＝假冒 B；C 自己寫 pack 校驗規則＝第二套 validator（被契約明文禁止）。
- **O-2 例外——import AST 為什麼合法**：見 C_MODULE_AND_DESIGN_REVIEW.md §B（要點：B 的契約明確不含 import；import 關係是 C 自己的推斷層，證據種類是 pinned blob 而非 code_fact，它不重建 B 的產品也不與 B 矛盾）。

### DEGRADATION（降級姿態）
- **G-1 每種依賴失效都有定義好的姿態**：pin 壞 → 拒絕；B 不可用 → DEGRADED + 安全子集繼續；pack 壞 → 整包棄用；pack 缺 → UNKNOWN/limits；讀取失敗 → UNKNOWN。禁止的姿態只有一種：**把失效偽裝成正常**（假 code_fact、假 validator、把讀取失敗當零）。
- **G-2 確定性**：相同固定輸入 + 相同外部觀察 → 位元組一致輸出（無時鐘、無隨機、排序遍歷）。為確定性刪除資訊是違規（確定性不能靠刪減達成）。
- **G-3 降級必須被看見**：status/limits/unresolved 必須讓消費者能區分「正常無提案」與「降級中的殘缺結果」。
