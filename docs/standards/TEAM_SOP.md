# ProjectMind 团队开发流程

这份文件只给人看。目标：我们按同一套最简单的流程开发。

## 一次任务怎么做

### 1. 先建任务
在 GitHub Issue 写清三件事：
- 要做什么
- 谁来做
- 做到什么算完成

例：
> 实现本地 Git 项目导入。能选择一个仓库并读取基础信息，导入失败时有提示。

### 2. 开自己的分支
不要直接改 `main`。

命名：
- 新功能：`feat/任务号-名字`
- 修 Bug：`fix/任务号-名字`
- 文档：`docs/任务号-名字`

例：
`feat/12-project-import`

### 3. 开发
可以使用任意 AI 辅助。

要求只有三条：
- 只做当前任务，不顺手大改别的东西
- 重要阶段及时 commit
- API Key、密码、Token 不上传

### 4. 自己先检查
提交前确认：
- 功能能不能跑
- 有没有明显报错
- 有没有误改无关内容
- 这次修改会不会改变“项目地图 / Project Model”

### 5. 提 PR
PR 就是“我做完了，请合进正式版本”。(merge)

写清：
- 做了什么
- 怎么验证
- 是否影响 Project Model
- 还有什么没解决

### 6. 检查后合并
另一名队员简单检查。(not must)
没问题 → 合并到 `main`。

合并后临时分支会自动删除。

---

## Project Model 什么时候要改

只问一句：

> 这次代码修改，有没有改变“这个项目由什么组成、模块负责什么、模块之间怎么联系”？

- 没有 → 不改
- 只是模块内部实现变化 → 可记一条变化，不改结构
- 新增/删除/拆分/合并模块，职责或重要依赖变了 → 要改
- 拿不准 → 交给人讨论

---

## 团队统一原则

1. `main` = 当前正式版本
2. 一个任务一个分支
3. 做完走 PR
4. 团队决定正式架构
5. Project Model 发生重要变化时必须由人确认
6. 能不用大模型解决的事情，不强行烧 Token
