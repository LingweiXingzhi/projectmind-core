# 共享服务器交接下载

已发布版本的同版交接包沿用 D 的 `architecture_handoff_v1` 格式，版本内容、`mapRevision` 和 `mapSourceRevision` 来自真实 B 不可变版本。

架构仓库没有 `origin` 时，私有服务器路径不能给另一台电脑使用，也不能公开到交接文件。导出现在仍可返回已发布版本内容，将 `sources.architecture` 设为协议已允许的 `null`，提示可阅读交接、跨电脑来源核验尚未完成。没有创建或声称存在 Git 下载地址，没有放宽摘要、版本或人审检查。

接收方可阅读文件。D 的 `inspect_version_handoff` 对此文件仍返回 `SOURCE_REQUIRED`，不能标成 `same_version_git_checked`。需要独立 Git 核验时，管理员应在明确授权后为架构仓库配置真实可用的远端，保存相应提交并让接收方取得该来源；不可把代码仓库 URL 冒充架构仓库来源。

已有真实架构远端时行为不变。代码来源为本机路径的已有项目仍被拒绝导出，不清除代码仓库身份、不伪造代码 SHA。未发布、草稿偏离发布版本和不一致的身份仍由既有治理入口拒绝。

## 页面使用

架构工作台发布后点击“导出同版交接包”，再点击“下载同版交接包 JSON”。“整理交接内容”会打开协同交接页。

共享服务器上的协同交接页使用已存在的真实工作区接口，不加载仅供本机人工地图使用的扩展 iframe：

- 交接包：选择项目，生成已发布版本交接包，再下载。下载绑定显示的图版本和架构来源提交；过期版本仍由接口拒绝。
- 延续上下文：整理已发布版本、未关闭任务和参与者工作记录，检查后复制或下载 Markdown。未发布项目使用明确标注的草稿；读取已发布版本失败时保持未知，不用新草稿替代。
- 工作日志：复用共享记录服务创建、编辑、查看历史或下载记录；写入保留会话身份及图/草稿 CAS 校验。记录不等于批准结论。

以上内容使用服务器现有持久化数据，未重新发布或自动批准用户图版本，也不读取服务端 API 密钥配置。接续者在同一网站登录后可选取同一项目；离线副本的独立 Git 来源核验仍受上述限制。
