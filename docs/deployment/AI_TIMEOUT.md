# 模型等待时间

生成候选和自然语言纠正使用同一个模型请求传输。默认总等待时间从 60 秒调整到 180 秒，以容纳较慢的完整架构输出。服务端可设置 `PROJECTMIND_AI_TIMEOUT_SECONDS`（有限正数，最大 600 秒）；配置无效会明确拒绝，不回显配置值。

时限包含进程排队、DNS/TLS、请求和现有 HTTP 400 兼容重试。重试不重置时限；超时或取消仍终止并回收工作进程。显式指定的连接测试 15 秒、变化解释 45 秒保持原来的调用策略。

这是等待策略，和 API 额度/回复 token 限制不同。共享模式现有无应用 token 上限策略未改；模型服务商自己的额度、响应速度和最大输出仍由服务商控制。没有改模型或供应商，没有使用样例冒充真实生成。

页面从服务端状态读取等待时长，显示最长约几分钟。收到成功候选后仍由用户决定是否应用到草稿，不自动确认或发布。

部署反向代理的等待时间应比模型总时限更长，为上下文准备和响应处理留出余量。本轮云端模型时限为 180 秒，Nginx 对现有 ProjectMind 上游的 send/read 等待调整到 240 秒；连接上游时限不调整。没有修改其他网站、TLS、账号或 API 密钥文件。
