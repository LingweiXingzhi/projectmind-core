# 在自己的服务器私下配置共享 API

目的：你自己输入 Key，老师无需 Key；Key 不经过聊天、GitHub 或老师的浏览器。
现有 Python 服务端负责调用模型，无需重写后端。服务器、备案域名仍需完成 HTTPS、登录和现有部署配置。

## 配置过程（由你在服务器上操作）

1. 按 README.md 的公网部署步骤准备服务，确认准确域名、HTTPS、账号、运行数据与架构 Git。
2. 把 deployment/ai.env.example 复制到 `/etc/projectmind/ai.env`，该路径位于应用源码和网站目录之外。
3. 你自己通过云平台的终端或 SSH 编辑该私有文件，在 `PROJECTMIND_AI_API_KEY=` 后填实际 Key，在 `PROJECTMIND_AI_MODEL=` 后填平台可用模型 ID。不要把填好后的文件、命令输出或截图发给 Codex。
4. 由服务器管理员将文件权限设为 0600，目录保持私有。systemd 服务模板已通过 EnvironmentFile 读取它；实际启用/重启服务需在你自己的服务器执行。
5. `PROJECTMIND_AI_SHARED_FROM_ENV=1` 开启托管模式：共享 Key/模型只来自服务端环境，忽略以前网页保存的共享 Key。共享配置页面只读，不回显 Key、不保存它到 SQLite。个人 API 保持独立，永不继承该 Key。已登录使用者可点击“检查 API 是否可用”，发送固定探测；这不提供任何配置权限。
6. 登录后检查 AI 状态，再按项目流程进行一次真实生成。老师打开同一 HTTPS 域名的 `/?demo=1#home`，登录后直接使用共享模型。

云平台有 Secrets/环境变量功能时，可在平台后台私下填写以上变量，不必使用文件。
本地启动也可设置同样变量，但同一电脑的 Codex 工具理论上能访问本机文件/进程环境；它不提供技术上的绝对隔离。
若要保证 Agent 接触不到 Key，请在未向 Agent 开放访问的服务器上自行配置，后续只共享源码和脱敏状态。
托管模式不清除旧私有配置文件；如以前已保存真实 Key，旧副本及备份需由你自行管理，不要公开。

## 使用与限额

默认实例总预算 50000 token、单次输出上限 2048；账本在私有数据根持久化，重启或配置改变不会清零。
平台模式不向老师展示绿色 token 数字；这些是后台限制，不是向老师承诺的可用平台余额。检查按钮也受后台预算约束，会产生少量模型用量。
所有通过该实例的生成、纠正、解释会占用同一共享额度；个人模式使用个人 Key 与独立预算。
额度不足会在发出模型请求前拒绝；未知用量/失败按保守预留计入，不是平台计费绝对上限。
服务端环境变更需重启。本轮没有登录你的服务器、读取任何真实 Key、执行 systemd 实机部署或调用千问。

## 验证范围

服务器托管模式的配置来源、页面不可修改/探测共享 Key、Key 不写入账本、不回显和个人配置不继承已通过合成凭据的自动化/HTTP 测试。
云资源、真实证书与供应商调用仍需要在你的真实环境完成；已有服务器和备案域名不等于服务已上线。
